# CQA - правила для агентов (Claude Code, Codex, Cursor и др.)

Проект: прототип Conversation Quality Analytics, кейс Freedom Broker на Data Challenge’26 (Nazarbayev University). Обзор и запуск - [README.md](README.md),
контракт API - [docs/API.md](docs/API.md).

## DEVLOG (обязательно)

Над репозиторием параллельно работают несколько людей и агентов. Общий бэклог - [DEVLOG.md](DEVLOG.md).

1. **Перед любой работой прочитай DEVLOG.md** на свежем `origin/main` (`git fetch && git show origin/main:DEVLOG.md`).
2. **Не бери задачи со статусом `[>]` и задачи, за которыми записан другой человек или агент.** Проверяй пересечение
   по файлам и смыслу, даже если у работы нет номера. Пересекается - не начинай, спроси пользователя.
3. **Взял задачу - сразу заяви её до начала кода:** строка `[>]` в индексе со следующим свободным `TASK-NNN`,
   кто (человек / агент), ветка и время (Астана), плюс раздел `## TASK-NNN` с областью файлов и критерием «готово».
   Закоммить только DEVLOG.md в `main` и запушь (`git pull --rebase` перед push). Заявка без push не считается.
4. **Во время работы** дописывай в раздел задачи важное: решения, грабли, что осталось. Одна-две строки, без воды.
5. **Закончил** - `[x]` и итог в одну-две строки (что сделано, где: ветка / PR). **Застрял** - `[!]` и причина.
6. Не трогай чужие ветки, рабочие копии и незакоммиченные изменения. Чужую задачу передают только через пользователя.

## Ограничения

- Код - в своей ветке и через PR. В `main` напрямую пушится только DEVLOG.md (заявки и статусы).
- Секреты не коммитить: `.env`, ключи API, сессии, токены. Видимость репозитория не менять - это решение команды.
- `results/*/results.json` собирать только кодом: `python -m cqa.submit` (формат JSON 1.0 из приложения к гайду).
- Перед push: `cd backend && python -m pytest -q`; если менялись эндпоинты - `python -m cqa.postman`.
- Тире в текстах - обычный дефис (-).
